个人多机 AI 知识库体系 v2

一个人 + 一群 AI agent + 多台电脑，如何共用同一个大脑 —— 架构、使用与维护实录

本地优先 · 不上云 git 同步 6 个常驻组件 每周维护 30 分钟

00这套体系解决什么问题

多台设备、多个 AI agent（Claude、Codex、自托管 bot 网关）协同工作时，最大的痛点不是模型不够聪明，而是组织：agent 之间没有共享记忆，每次都要重新理解你；改动无法传递；维护体系本身的成本吞掉了它带来的生产力。

v1 时代的教训（真实数据）：治理规则 45+ 条、三层元管理嵌套、每次会话写回约 10 个文件、双向同步连挂三天、136 项全量审计只发现 1 个真实故障——两周 14 篇工作日志里 12 篇是在修体系本身。

v2 的答案是一句话：用 git 当 agent 之间的通信总线，用一页规则替代全部治理，用「删掉它 agent 会不会变笨」当唯一的存在性判据。

01架构总览

另有一台业务隔离机承担生产业务，红线是「稳定来自无聊」：不装新工具、不做实验、不克隆知识库（要读资料 ssh 到服务器看）。每台机器一个角色，互不越界。

02五条设计铁律

判别法（最重要的一条）：删掉这个文件，agent 下次干活会不会变笨？会 → 它是工作上下文，保留；不会 → 它是报告，删掉或交给脚本自动生成。所有「要不要建 XX」的争论都终结于这一刀。
不建索引是决定，不是疏漏：agent 有 grep，目录名就是索引。任何需要人工保持同步的索引、导航、清单都不许存在——它们正是 v1 累死人的根源。
协作走 git（双向），备份管道永远单向：把这两件事混成一件（双向文件同步当备份）是 v1 同步连挂三天的根因。
面板只许自动生成，通知只在失败时发：绿灯不需要报告。给自己交付，消息比面板好。
新增任何东西前先问每月人工维护成本：必须趋近于 0，否则不进体系。宁可笨而稳，不要聪明而脆。

03常驻组件（恰好 6 件）

组件干什么
kb-sync.sh + 定时任务每 15 分钟自动「收口本地改动 → pull --rebase → push」。离线 = 正常，静默；冲突 = 回退安全态 + 本地只通知一次（macOS 用 launchd，Linux 用 cron，同一脚本跨平台）
kb 终端命令坐下敲一下：同步 + 列出「你不在时谁干了什么」+ 显示 NEXT.md；兼任 72 小时失联黄字报警
m4 命令 + SSH 别名一键进家庭服务器的 tmux 跑长任务（断线不丢）；所有脚本只引用别名，换 IP 只改一处
仓库内三个配置.gitattributes（追加型文件 merge=union 自动合并）、.gitignore（媒体大文件不入库）、AGENTS.md 一页规则（CLAUDE.md 是它的符号链接，Claude 与 Codex 读同一份真相）
默认模型 = 中档日常用性价比模型，大决策手动切旗舰；不建任何自动路由机制
~/.secrets 约定密钥唯一登记簿（只在服务器、磁盘加密保护）；agent 规则：密钥只从这里读、新密钥先登记、永不进 git

04知识库内部结构

文件 / 目录角色写入纪律
AGENTS.md唯一规则真相（一页、8 节）基本不动
START.md开工卡片：丢给任何 agent 它就知道怎么做不动
NEXT.md在做的事，上限 3 件只在收工时整文件重写
IDEAS.md想法收件箱，一行一条只追加，永不改旧行
PROJECTS.md项目登记簿（名称/状态/位置/一句话）开/关项目时加一行
MACHINES.md设备角色与红线、新机接入命令只有人手动改
runbooks/修复技能库：症状 → 原因 → 命令 → 验证只新建/更新同症状篇
50-工作日志/每会话一篇，日期-机器-主题.md只新建
90-归档与未审/历史快照（旧体系全部归档于此）默认不读，只读不写
主题目录（业务/技术…）真正的知识内容正常读写

防冲突的全部秘密：高频写入全是「追加型」（IDEAS、日志、runbook）配 merge=union 自动合并；唯一的「状态型」共享文件只有 NEXT.md 一个，且每次整文件重写自带自愈。实测多 agent 并行写一个月，真实冲突 ≈ 每月 0–1 次，处理方式是弹一次通知 + 3 分钟照 runbook 解决。

05日常怎么用

开工（任何机器、任何 agent）

对 agent 说一句：「读 ~/knowledge-base/START.md 照做」。它会自动同步、读 NEXT、用三句话汇报「你不在时发生了什么、现在排着什么、建议先做哪件」，然后等你指示。在网页版或新工具里，直接把 START.md 内容粘贴进对话，效果相同——这张卡片跟着文件走，不跟机器走。

同时每台机器的 Claude / Codex 全局配置里都立了「指路牌」（知识库位置 + 开工收工规则），所以即使你什么都不说，agent 通常也会自己照做。

收工

说「收工」，agent 按规则执行：整写 NEXT → 写一篇工作日志 → 修复类工作沉淀 runbook → commit + push。经验从此变成资产而不是消耗：同一个故障第二次出现时，任何 agent 五分钟照方抓药。

想法

随时随地让手边的 agent往 IDEAS.md 追加一行。记下来 ≠ 要做——想法有了去处，脑子就不用一直挂着。

移动场景

手机发 Telegram → 家庭服务器上的 agent 干活（它有完整知识库和密钥）→ 结果写回 git → 你在任何电脑上 pull 即见。手机是遥控器，服务器是引擎，知识库是传送带。

06备份与安全（四层冗余，全自动）

层什么频率
1每台机器的 git 克隆 = 完整历史副本（git 免费送的）每 15 分钟
2正本镜像到外接加密盘（含密钥、换机工具包、Brewfile）每晚
3带日期的 git bundle 存档到冷备份大盘（保留 8 周）每周
4自动验证备份可恢复（fsck + bundle verify），失败才告警每周日

告警通道很取巧：验证失败时直接往知识库写一篇告警文件并 push——你下次开工时 agent 自然汇报，零新增通知系统。安全侧：服务器与笔记本全盘加密；密钥集中登记；runbooks/设备丢失-笔记本.md 预写好 15 分钟吊销清单（断网内身份 → 断 SSH → 远程抹除 → 吊销凭据）。

07维护：每周五 30 分钟，到点硬停

1. 一周提交体检：auto 提交占比异常高 = agent 没按收工走，下次开工点名
2. NEXT.md：过期的删，保持 ≤3 件
3. 收件箱清零：每个文件 → 挪进主题目录 / 压成 IDEAS 一行 / 直接删
4. IDEAS 扫一遍：挑 0–1 条进 NEXT，其余不动
5. 翻本周日志：修过的东西 runbooks/ 里有没有对应条目？没有就当场补
6. 到 30 分钟硬停，没做完的下周五再说

这是整个体系唯一的固定维护时间。衡量体系健康的朴素标准：连续一周没有为基础设施开过一次「修复会话」。管理系统唯一的 KPI 是你多久不需要看它。

08接入一台新机器（约 2 分钟）

新 Mac 跑一条引导命令（脚本存在服务器上）：自动完成 SSH 免密 → 克隆知识库 → 防冲突 git 配置（pull.rebase、autoStash、机器名作提交者）→ 装自动同步 → 装 kb/m4 命令 → 设默认模型。Linux 机器同样克隆，把 launchd 换成一条 cron 即可。换电脑剧本：插上加密外接盘（每晚载有完整镜像与换机包）→ 跑引导 → 半小时恢复全部工作环境。

09踩坑实录（每个坑都变成了 runbook）

macOS TCC 静默拦截：launchd 后台任务无权读 ~/Documents（退出码 127、手动跑却正常、两台机器同病）。修法不是点权限弹窗（点错一次=永久静默失败），而是把库整体迁出受保护目录。铁律：自动任务的路径避开 Documents/Desktop/Downloads。
幽灵挂载点：外接盘未挂载时向 /Volumes/盘名 写入，macOS 会在内置盘悄悄建同名假目录 → 真盘再挂载变成「盘名 1」→ 双正本静默脑裂。所以正本放永远在线的内置盘，外接盘只当镜像；所有触盘脚本先验挂载哨兵。
双向同步是陷阱：rclone bisync 连挂三天的根因是把「协作」和「备份」混成一件事。git 天然解决协作（每个克隆都是完整副本），备份管道保持单向后这类故障永久消失。
不验证的「成功」不算成功：曾有一整轮施工因终端异常而全部未持久化，但回显全是 ✅。此后铁律：每次 commit 后立刻 git log 验证落地；复杂操作写成脚本文件再执行；备份必须每周自动做恢复演练。
护栏自己也会变成噪音源：大文件护栏因不幂等导致排除清单膨胀 40 倍、每 15 分钟弹一次通知。任何自动护栏都要问一句：它失效或重复触发时，谁来守护护栏？（答案：幂等设计 + 只在状态变化时发声。）

10给想抄作业的人：三步起步

第一步：把笔记目录变成 git 仓库，在常开的机器上建裸仓库当正本，其他设备克隆。第二步：写三个文件——NEXT.md（在做 ≤3 件）、IDEAS.md（想法只追加）、一页 AGENTS.md（开工 pull 读 NEXT / 收工整写 NEXT 写日志 push / 密钥永不进 git）。第三步：给 agent 的全局配置加一句指路牌，装一条 15 分钟的同步定时任务。

就这些。其余一切——备份链、runbook、防冲突配置——都可以等真的痛了再加。这套体系最大的教训恰恰是：先用最小集跑起来，警惕任何「为了管理而管理」的冲动。
